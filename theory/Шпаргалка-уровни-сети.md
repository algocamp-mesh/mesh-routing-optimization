# Шпаргалка: что внутри чего в сетях

## 1. Главная идея: сеть — это слоёный пирог

Каждый слой решает одну задачу и пользуется слоем ниже, не вникая в его устройство.

| Слой                                        | Какой вопрос решает                                                          | Аналогия с дорогами                 |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Приложение                            | Что передаём?                                                                      | Груз в машине                             |
| Маршрутизация (сетевой)     | Через кого передать, чтобы дошло до адресата?            | Навигатор: каким путём ехать |
| Доступ к эфиру (канальный) | Когда мне можно говорить, чтобы не перебить соседа? | Правила проезда перекрёстка |
| Радио (физический)               | Как превратить биты в радиоволну и обратно?               | Тип дороги и двигатель            |
| Железо                                    | Чем всё это физически делается?                                     | Конкретная машина                    |

## 2. Карта: кто где находится

```
                  МИР Wi-Fi                 МИР LoRa                   НАШ ПРОЕКТ
              ┌───────────────────────┬──────────────────────────┬──────────────────────────┐
 Приложение   │ браузер, мессенджер   │ чат и GPS в Meshtastic   │ сообщения с телефона     │
              │                       │                          │ (по Bluetooth, вне модели)│
              ├───────────────────────┼──────────────────────────┼──────────────────────────┤
 Маршрути-    │ AODV, DSR, OLSR,      │ затопление Meshtastic,   │ ★ ЭТО МЫ И ПРИДУМЫВАЕМ ★ │
 зация        │ B.A.T.M.A.N., Babel   │ MeshCore, Reticulum,     │ затопление + Q-routing   │
              │                       │ LoRaMesher               │                          │
              ├───────────────────────┼──────────────────────────┼──────────────────────────┤
 Доступ к     │ 802.11 MAC            │ «послушай, потом говори»,│ полудуплекс, коллизии,   │
 эфиру        │ (CSMA/CA)             │ лимит эфирного времени   │ лимит эфира (дано)       │
              ├───────────────────────┼──────────────────────────┼──────────────────────────┤
 Радио        │ Wi-Fi 802.11, OFDM    │ LoRa, CSS-модуляция      │ LoRa SF7, 125 кГц (дано) │
              │ 2,4/5 ГГц, Мбит/с     │ 868 МГц, ~0,3–5 кбит/с   │                          │
              │ дальность ~100 м      │ дальность — км           │                          │
              ├───────────────────────┼──────────────────────────┼──────────────────────────┤
 Железо       │ Wi-Fi-чип роутера     │ SX1262 + nRF52840/ESP32  │ SX1262 + nRF52840 (дано) │
              └───────────────────────┴──────────────────────────┴──────────────────────────┘
```

Главное из карты:

- **LoRa и Wi-Fi** живут внизу. Это способы передать биты по радио. Про маршруты они ничего не знают.
- **AODV, DSR, OLSR** живут на этаже маршрутизации. Они не привязаны к радио: их придумали под Wi-Fi, но в теории их можно запустить и поверх LoRa. На практике там они тратят слишком много эфира.
- **Наш проект — один этаж: маршрутизация.** Всё, что ниже (LoRa, чип, лимиты), нам дано как условия.

## 3. Алгоритм → протокол → продукт

Эти три слова часто путают. Они стоят в цепочке от идеи к готовой вещи.

```
 АЛГОРИТМ                ПРОТОКОЛ                        ПРОДУКТ / ПРОШИВКА
 (идея, математика)      (точные правила и форматы       (готовая программа, которую
                          пакетов, о которых все узлы     ставят на устройство)
                          договорились)

 Дейкстра  ─────────────▶ OLSR ─────────────────────────▶ olsrd (Linux-демон)
 Затопление ────────────▶ правила ретрансляции ─────────▶ прошивка Meshtastic
                           Meshtastic
 Поиск пути по запросу ─▶ AODV, DSR ───────────────────▶ реализации в Linux и в симуляторах
 Q-learning ────────────▶ Q-routing ───────────────────▶ ★ наш метод (пока в симуляторе)
```

- **Алгоритм** — способ решения: как найти кратчайший путь, как разослать всем.
- **Протокол** — договорённость: какие поля в пакете, когда отвечать, сколько ждать. Протокол обычно использует один или несколько алгоритмов.
- **Продукт** — конкретная реализация, часто сразу на всех этажах.

## 4. Продукт занимает целую колонку, протокол — одну клетку

```
                 AODV          Meshtastic (продукт)
 Приложение                    ██ чат, GPS, приложение на телефоне
 Маршрутизация   ██            ██ управляемое затопление
 Доступ к эфиру                ██ свои правила доступа к эфиру
 Радио                         ██ LoRa
 Железо                        ██ список поддерживаемых плат
```

Поэтому нельзя сравнивать «Meshtastic или LoRa»: Meshtastic **использует** LoRa.
А «Meshtastic или AODV» сравнивать можно, но только по этажу маршрутизации.

## 5. А «технология» и «mesh» — это что?

- **Технология** — размытое бытовое слово, «семейство всего вокруг одной идеи». «Технология LoRa» = модуляция + чипы + экосистема. «Технология Wi-Fi» = набор стандартов 802.11.
- **Mesh (сетка)** — не технология и не протокол, а **форма сети** (топология): узлы связаны друг с другом напрямую и передают чужие пакеты. Противоположность — **звезда**: все говорят только с центром (Wi-Fi-роутер, вышка сотовой связи).

```
   ЗВЕЗДА                     MESH (сетка)

     A   B                    A ─── B
      \ /                     │ ╲   │
   ── [ЦЕНТР] ──              │  ╲  │
      / \                     C ─── D ─── E
     C   D
   всё через центр            каждый — ретранслятор
```

Mesh можно построить на любом радио:

- Wi-Fi mesh: стандарт 802.11s, домашние mesh-системы, B.A.T.M.A.N.;
- LoRa mesh: Meshtastic, MeshCore.

**Частая путаница: LoRaWAN — это не mesh.** Это звезда поверх LoRa: датчики говорят с базовой станцией (шлюзом). Тот же LoRa внизу, совсем другая сеть сверху.

## 6. Одной фразой

> LoRa — как передать биты по радио далеко и медленно; mesh — форма сети, где каждый узел передаёт чужие пакеты; протокол маршрутизации (AODV, DSR, затопление Meshtastic, наш Q-routing) решает, кому передать пакет дальше; Meshtastic — готовый продукт, где всё это собрано вместе.
