# Маршрутизация в подвижной Mesh-сети LoRa: AODV и гибрид

Кейс: подвижная сеть LoRa (SX1262, SF7). Требования:
- до 20 узлов;
- потери ≤ 10 %, задержка ≤ 20 с;
- ОЗУ 200 кБ, ПЗУ ≤ 100 000 перезаписей за 5 лет.

## Результат

Доля пакетов, доставленных не позже 20 с (PDR за 20 с). 20 подвижных узлов на 2 × 2 км, случайные пары, 0,2 пакета/с на всю сеть, по 20 повторов (исследования 1–2).

| Метод | Пешеходы | Техника | Дроны | Задержка ср. | Эфир на пакет |
|---|---|---|---|---|---|
| Затопление | 0,852 | 0,855 | 0,863 | 0,3 с | 1,3 с |
| AODV по RFC 3561 | 0,800 | 0,769 | 0,757 | 4–5 с | 2,1 с |
| `aodv_lora`: AODV + 4 доработки под LoRa | 0,915 | 0,903 | 0,903 | 4–5 с | 1,9–2,3 с |
| **`hybrid`: `aodv_lora` + пакет в RREQ + «храни и неси»** | **0,928** | **0,948** | **0,958** | 3–4 с | 1,9–2,3 с |
| Эталон Дейкстры (знает всю карту сети) | 0,916 | 0,919 | 0,920 | 0,3 с | 0,34 с |

Все варианты в разных условиях (исследование 4, раздел 11.5; PDR за 20 с, по 10 повторов, среднее по видам движения):

| Метод | Случайные пары | Все → координатор | Узлы пропадают | Нагрузка 0,5 пак/с | Неподвижные топологии (6 шт.) | Эфир на пакет, с |
|---|---|---|---|---|---|---|
| Затопление | 0,857 | 0,881 | 0,768 | 0,801 | 0,533 | 1,35 |
| Затопление ×3 (контроль) | 0,925 | 0,929 | 0,837 | 0,862 | 0,810 | 3,45 |
| 1. AODV по RFC | 0,782 | 0,696 | 0,708 | 0,643 | 0,329 | 2,13 |
| 1. `aodv_lora` | 0,909 | 0,905 | 0,804 | 0,568 | 0,805 | 2,09 |
| 2. `hybrid` | 0,950 | 0,931 | 0,848 | 0,723 | 0,826 | 2,10 |
| 3. `hybrid_dc` | 0,951 | 0,923 | 0,845 | 0,826 | 0,815 | 2,09 |
| **4. `hybrid_plus`** | **0,944** | **0,924** | **0,849** | **0,823** | **0,911** | 2,22 |

- **AODV по RFC на LoRa не работает.** 78–99 % «обрывов канала» ложные: подтверждение тонет в коллизии с волной поиска RREQ.
- **`aodv_lora`** выходит на уровень эталона Дейкстры. Главные доработки — локальная починка маршрута и повторы с нарастающей паузой.
- **`hybrid`** доставляет больше эталона. Первый пакет едет внутри RREQ, и пока нет ответа, он рассылается заново с каждым поиском: это затопление с повтором до подтверждения. Так доходят и пакеты, для которых в момент отправки пути не было.
- **`hybrid_dc`** держит нагрузку. Узел, израсходовавший 60 % своего лимита эфира, перестаёт пересылать чужие RREQ: при 0,5 пакета/с доставка +0,10, эфира −35 %. Отключение данных в RREQ при перегрузке проверено и вредно.
- **`hybrid_plus`** чинит цепочки. Узел с ≤ 2 соседями повторяет RREQ, если не услышал, что его переслали дальше: неподвижные топологии 0,82 → 0,91, линия 0,76 → 0,98.
- **Ресурсы:** ОЗУ ~3 кБ, ПЗУ ~10 тыс. перезаписей за 5 лет (номер последовательности пишется блоками).
- **Ограничения:**
  - потери ≤ 10 % держатся до ~0,3 пакета/с на сеть;
  - при частом пропадании узлов требование не выполняет ни один метод.

## Как запустить

Зависимости: Python 3.10+, `pandas`, `matplotlib`, `jupyter`.

Откройте блокнот и выполните *Restart & Run All*. Результаты берутся из `results/`, прогон занимает около минуты. Полный пересчёт — `RERUN = True` в первой ячейке экспериментов: от 40 минут до нескольких часов на одном ядре.

Блокноты собираются из `tools/cells/`. Чтобы изменить код или текст, правьте ячейки там и пересобирайте:

```
python tools/build_aodv.py                          # 1_simple_aodv.ipynb из theory/ + tools/cells
python tools/build_studies.py                       # 2–4 из 1_simple_aodv.ipynb + tools/cells (можно указать имя)
python tools/precompute.py 4_reliable_rreq.ipynb   # недостающие CSV в results/ параллельно на всех ядрах (--force — пересчитать все)
python tools/execnb.py 4_reliable_rreq.ipynb       # выполнить блокнот и сохранить графики
```
