## Результаты экспериментов

Источник: сохранённые таблицы [mesh_routing_simulation.ipynb](mesh_routing_simulation.ipynb). Все показатели перенесены без пересчёта; таблицы одного сценария объединены по сценарию и алгоритму. Названия столбцов сохранены как в ноутбуке: latency_mean_s — средняя задержка (mean_latency). PDR и доли указаны от 0 до 1, время — в секундах, энергия — в джоулях. Знак ± обозначает стандартное отклонение между прогонами; «—» — неопределённое значение при отсутствии доставленных пакетов. Счётчики fail_* и другие счётчики усреднены по прогонам и могут быть дробными.

| Критерий | Flooding | Dijkstra | DP с HopLimit | DSR |

| Принцип работы | Распространение DATA по соседям с подавлением дубликатов | Минимальная стоимость пути по текущему графу | Минимальная стоимость пути при ограничении числа переходов | Поиск через RREQ/RREP и передача по найденному пути |

| Выбор по ETX | Нет выбора единственного пути | Учитывается в стоимости рёбер | Учитывается в стоимости рёбер | Сравниваются полученные варианты |
| HopLimit | Ограничивает распространение копий | Проверяется при передаче, но не при выборе пути | Учитывается при поиске пути | Ограничивает поиск и передачу |

## Сравнение в разных условиях

| Условия | Сопоставление методов |
|---|---|
| Стабильная сеть | Dijkstra и DP выбирают путь по известному графу. DSR повторно использует кэш без нового поиска. Flooding распространяет копии каждого пакета. |
| Малый HopLimit | DP ищет допустимый путь сразу. Dijkstra может выбрать более дешёвый путь, превышающий лимит, даже при наличии более дорогого допустимого пути. DSR и Flooding ограничивают распространение запросов или DATA. |
| Подвижность и отключения | Кэш DSR может устареть, восстановление требует времени и эфира. Flooding использует несколько ветвей. Dijkstra и DP получают новый снимок графа для следующего пакета, но не перестраивают автоматически путь пакета в передаче. |
| Высокая нагрузка | Копии Flooding и запросы DSR конкурируют за эфир. Адресные методы передают DATA вдоль одного пути, однако ACK и повторы также создают нагрузку. Преимущество по доставке и задержке определяется измерениями. |
| Ограничение duty cycle | Все методы могут ожидать разрешённого времени передачи. Flooding расходует бюджет на копии DATA, DSR — также на поиск и восстановление маршрутов. |

## Интерпретация результатов

Dijkstra и DP в этой модели — эталоны с доступом к актуальному глобальному графу. Затраты на сбор топологии и вычисление маршрута не моделируются. DSR обнаруживает путь через радиообмен, поэтому его задержка и расход эфира включают работу поиска маршрута. Разница отражает как выбор пути, так и различие доступной информации.

Для сравнения используются следующие показатели:

- **PDR:** доля доставленных пакетов.
- **Средняя и p95 задержки:** скорость доставки и выраженность длинных задержек. Они считаются по доставленным пакетам, поэтому меньшая задержка при низком PDR сама по себе не означает преимущество.
- **Эфирное время и число передач на доставленный пакет:** стоимость успешной доставки с учётом потерь и повторов.
- **Служебный трафик:** у DSR учитывать RREQ/RREP/RERR вместе с ACK. В ноутбуке `overhead_share` учитывает только ACK, а маршрутизация выделена в `routing_control_share`.
- **Энергопотребление:** сопоставлять с количеством успешно доставленных пакетов.

Flooding использует несколько ветвей ценой передачи копий. Dijkstra минимизирует стоимость пути без учёта HopLimit при поиске. DP учитывает ограничение хопов заранее. DSR передаёт данные по маршруту, который необходимо обнаружить и поддерживать служебным обменом.
